# 路线图

> 状态会随实现更新。每个里程碑都附带可执行验收，不以“完成了”口头通过。

## M0 契约与试点 harness

- [x] 任务契约 JSON Schema v0.1
- [x] 影子试点 harness（派发 / 回收 / 复核 / 失败注入）
- [x] 证据锚点自动校验（路径 + 行号 + 原文引用）
- 验收：三路并行 + 一路复核跑通；三类失败注入均判 failed。

## P0 真实只读评审试点

- [x] 一次真实只读评审（n=1）
- [x] 4/4 结果通过校验；失败注入 3/3；证据负向用例 2/2
- [x] 独立复核：确认 29 / 待验证 1 / 分歧 1
- 报告：[pilot-p0.md](pilot-p0.md)

## M1 dsh headless adapter

- [ ] 派发接口：任务文本 → 后台进程（stdin、独立工作目录、超时）
- [ ] 心跳：间隔、stale 阈值、进程树终止留痕
- [ ] 回收：退出码 / 超时 / 结构化结果三重校验
- 验收：成功 1 例 + 失败注入 3 例，全部可复现；失败不包装成成功。

## M2 独立复核 /review

- [ ] reviewer 会话：读取原始证据（不读执行者摘要）
- [ ] 证据锚点校验：不存在路径 / 越界行号 / 引文不匹配均拒绝
- [ ] 复核输出：已证实 / 待验证 / 分歧，严重性可上下调
- 验收：reviewer 必须能拒绝伪造锚点；对已知错误结论给出降级理由。

## M3 台账与续跑

- [ ] `runs/<id>/` 结构：spec / spans / status / report / heartbeat
- [ ] 步骤状态机 + 幂等键 + 原子提交
- [ ] `/run status`、`/run resume`：中断后不重复已完成分支
- 验收：人为中断后 resume，产物不重复、状态可重放。

## M4 聊天内决策队列 /decide

- [ ] 待决事项卡片（选项 + 证据 + 默认动作）
- [ ] 无响应时的超时/升级规则
- [ ] 高风险动作（发布、权限、删除）强制等待批准
- 验收：无人响应不会替用户拍板；高风险动作不越权执行。

## M5 跨 harness adapter

- [ ] Codex exec adapter
- [ ] Claude `-p` adapter
- [ ] 统一契约与失败语义（不同 harness 的退出码/超时映射）
- 验收：同一任务在 dsh / Codex / Claude 上跑同一契约，结果可对比。

## M6 发布

- [ ] npm 包（`dsh-conductor`）+ `dsh-plugin` topic
- [ ] 插件市场提交与目录收录
- [ ] 文档、示例、演示视频
- 验收：干净环境一次安装可用；README 与实现一致。

## 已知缺口（不阻塞发布，但需公开说明）

- 重启恢复 / 写操作回滚 / 权限强制边界 / 产物内容正确性 / 成本口径；
- P0 为 n=1 的只读评审，稳定性需要更多真实任务样本。
