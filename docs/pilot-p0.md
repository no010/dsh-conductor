# P0 影子试点报告

> 状态：**completed**（单次只读评审，n=1）。本报告来自一次真实运行，代码位于试点 harness（未公开，随插件 MVP 一起整理）。

## 1. 试点目标

验证「契约 → 派发 → 回收 → 独立复核 → 失败暴露」链路是否可靠，作为插件 MVP 的准入判断。

## 2. 设置

- 任务：对一份本地产品策划文档做只读评审（三个维度：product / technical / risk）；
- 执行：三路 dsh headless 并行分析（各自独立 `DSH_HOME` 与工作目录）+ 一路独立 reviewer；
- 契约：证据锚点必须为「文件 + 行号 + 原文引用」，机器校验；含 2 条负向用例；
- 失败注入：非零退出、超时、结构化结果缺失，各自在独立目录执行；
- 通过条件：退出码 0、未超时、结构化结果通过校验、每条结论的证据锚点成立。

## 3. 运行过程

| 轮次 | 结果 | 原因 / 修复 |
|---|---|---|
| 第 1 次 | failed | dsh 模型接口瞬时不可达；按契约记录 blocker 并停止，未改派 |
| 第 2 次 | failed | 网络恢复；一路已产出合法结论，但解析器只接受纯 JSON（输出夹带推理文本） |
| 第 3 次 | failed | 解析器修复后三路分析全部通过；reviewer 撞上 180s 超时 |
| **第 4 次** | **completed** | 超时提高到 600s；4/4 通过，无 blocker |

> 修复项：`parse_result()` 支持「推理文本夹带 JSON / 代码块 / 纯 JSON」三种真实输出形态；reviewer 采用更大超时。

## 5. 复核结果

- 确认 **29 条**（high 9 / medium 19 / low 1）；
- 待验证 1 条；分歧 1 条（reviewer 将一条 high 下调为 medium，并给出理由）。

高严重度结论集中在：恢复/续跑缺少幂等与检查点、产物完整性与内容正确性未被三重校验覆盖、权限只有声明没有强制边界、dsh adapter 未设为 P0 硬退出门、reviewer 独立性未定义隔离强度。

## 6. 证明了什么 / 没证明什么

**证明**

- 多人格并行评审可以被机器化编排与回收；
- 证据锚点可被自动校验（路径/行号/引文）；
- 三类失败在独立注入下均被 fail-closed 拒绝；
- 独立复核能下调执行者严重性、纠正绝对化结论；
- dsh headless 可以被程序化派发并回收（真实成功路径跑通一次）。

**未证明**

- 恢复/续跑、写操作回滚、权限强制边界、跨 harness 派发；
- 产物完整性与内容正确性；
- token/成本口径；
- n>1 的稳定性。

## 7. 对 MVP 的影响

1. 把「恢复、权限、产物完整性」从 MVP 门禁降级为专项验证，或先做最小切片；
2. 契约增加 schema 版本、产物清单/哈希校验、决策与审批记录；
3. P0 补充「退出码 0 但产物缺失」「JSON 合法但内容错误」两类负向用例；
4. 复核隔离强度（盲评、模型差异、抽查比例）写进契约。
