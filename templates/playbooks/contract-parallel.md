# 模板：并行任务 + 统一验收契约（contract-parallel）

**适用**：彼此独立、可按同一标准检查的任务（多篇调研、多个模块审查、多份文档）。

**为什么**：并行的收益取决于“结果能不能被单独验收”；没有统一契约，并行只会把混乱放大。

## 输入

- 任务清单（每路一个可独立交付的产物）；
- 统一验收标准：原文核验、证据分级、格式、完成定义；
- 每路的输出路径（互不覆盖）。

## 步骤

1. **先写契约再派发**：每路交付什么、怎么算完成、证据放哪里，写清楚。
2. **一路一目录**：产物写各自 `artifacts/<role>/`，禁止并发写同一路径。
3. **统一入口**：同一份任务说明模板，只替换维度/材料，减少解释成本。
4. **失败即停**：任一路失败则记录 blocker，其余在途步骤取消；不改派、不假装成功。
5. **统一回收**：全部完成后才进入复核；按同一标准逐路验收。
6. **汇总**：主 agent 负责合并、去重、标注未完成与分歧。

## 验收

- 每路产物可单独打开并核对；
- 任一路失败都有明确原因，且不被其他路的成功掩盖；
- 交付物中不出现两路互相覆盖的路径。

## 常见失败

- 多路共用同一输出目录 → 产物互相覆盖；
- 失败后静默重试或换路 → 用户看到的“成功”不可信；
- 没有统一验收标准 → 结果无法比较。
