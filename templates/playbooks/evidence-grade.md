# 模板：分层取证 + 新事实修正（evidence-grade）

**适用**：信息不完整、结论可能随新证据变化的排查/调研任务。

**为什么**：把“观察到”当成“已证实”，会把未知变成错误结论；把未知如实保留，才能在下一次检查中修正。

## 分级

| 级别 | 含义 | 表达 |
|---|---|---|
| 已证实 | 有可复核的原始证据（输出、日志、测试、原文） | 直接陈述 + 证据锚点 |
| 待验证 | 有迹象但证据不足，或只有间接证据 | 明确标注“待验证”，给验证方式 |
| 未知 | 无法获取或未检查 | 明确写“未知”，不得用 0 或默认值代替 |

## 步骤

1. **先列未知**：哪些信息没拿到、为什么、需要什么才能拿到；
2. **只做只读检查**：在不改变系统的前提下收集证据；
3. **分级记录**：每条结论标注级别与证据；
4. **不推断过度**：健康检查正常 ≠ 能力已验证；进程退出 0 ≠ 交付正确；
5. **新事实出现后修正**：记录旧结论、新证据、修正理由，不静默改写历史；
6. **输出**：结论 + 证据 + 未验证项 + 下一步验证方式。

## 验收

- 报告能区分“已证实 / 待验证 / 未知”；
- 未知项没有被默认值或乐观推断填充；
- 结论变化有旧结论、新证据与理由。

## 常见失败

- “服务可用”被写成“受控能力已验证”；
- token/成本缺失时记 0；
- 新证据出现后直接改结论，不留下修正痕迹。
